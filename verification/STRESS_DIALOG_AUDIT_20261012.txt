Stress dialog audit - 12 October 2026

Main finding
The Windows save dialog confirmed replacement, but create_study then rejected
every existing filename. The UI could also leave its progress bars spinning
after this failure. Confirmed replacement now creates a new study and retains
the previous JSON beside it as a dated *.previous-*.stress.json backup. Existing
trial directories remain intact. Opening a saved study remains the resume path.

Additional fixes
- Prevent duplicate startup while Qt processes events or the file picker is open.
- Lock the study across coordinators and replacement operations, with automatic
  OS lock release when the owning process exits.
- Keep a running dialog visible when Escape or Close is pressed.
- Reset progress and unlock the editor after failed startup or worker exit.
- Report external cancellation as stopped, and completed resume as complete.
- Validate opened files before replacing the currently loaded study.
- Preserve saved numeric precision and support seeds beyond the widget range.
- Restore study settings button allows recovery after editing a frozen setup.
- Keep the current retry error visible instead of replacing it with an old error.
- Reject resume/finalization if another window replaced the study file.
- Keep worker termination scheduled even if the stop-request file cannot be saved.
- Preserve the old study if a stale stop-request file cannot be removed.
- Disable review actions and corridor highlighting immediately during startup/run.

selected the existing native-overwrite.stress.json, clicked Save and confirmed

disposable process afterwards. The user's unsaved LTN project was not replaced.
