# AMR simulation verification matrix

Compare the existing workflow entry points against the rollback revision on the same inputs. Record the source version, frozen input and drawing hashes, configuration, operating system, Python, hardware and evidence format. For this audit, the existing tests are the regression evidence. Engine and accelerator timings from the separate lean prototype are provisional.

| Workflow | Entry point and representative checks | Acceptance for an engine change |
|---|---|---|
| Original LTN week, Simple | [Managed execution](../amr_project_runs.py) with the original frozen week, floor-2 waypoint, lift policies, compact event store and normal queue drain | Exact task outcomes, ordered full-precision events, selected routes and bookings, complete final robot/lift/inventory state. On the stock Ryzen 7 9700X reference desktop with Windows x64 and local NVMe, all three fresh CPU-only runs finish within 60 seconds. |
| Explicit Simple | [Managed execution](../amr_project_runs.py) and [mode and compact acceptance tests](../tests/test_mode_simulation_acceptance.py) | Preserve simple graph route order, edge/node boundary decisions and full results across normal and constrained demand. |
| Detailed and legacy geometric compatibility | [Managed execution](../amr_project_runs.py) with [explicit mode tests](../tests/test_mode_simulation_acceptance.py), [occupancy](../tests/test_occupancy_simulation.py), [recovery](../tests/test_recovery.py) and [partial-run tests](../tests/test_partial_run.py) | Preserve mode selection, trajectories, occupancy, recovery choice, energy, resolved work and exact partial termination evidence. |
| Native and explicit demand | [Generator](../amr_sim_task_generation.py) and [simulator](../simulator.py) with [provenance](../tests/test_generation_provenance.py), [demand boundaries](../tests/test_generation_boundaries.py) and [explicit payload identity](../tests/test_explicit_payload_identity.py) | Preserve generated identifiers, calendar, release/deadline time, return lineage, random draw order, and pickup/drop-off and payload state. Include simultaneous releases, deferrals, overnight shifts and threshold crossings. |
| Routing and reservations | [Simulator](../simulator.py), [forced routes](../tests/test_forced_floor.py), [bed fallback](../tests/test_bed_lifts.py), [booking order](../tests/test_lift_reservation_order.py) and [atomicity](../tests/test_route_reservation_atomicity.py) | Check equal routes and lift scores, destination-side criteria, scenarios, window boundaries, private bookings, edge/node scans and no-overtaking. Exercise late refusal and rollback of all resource and evidence state. |
| Scenario and stress | [Scenario evaluation](../amr_scenario_study.py) with [scenario cases](../tests/test_scenario_study.py), [parallel execution](../tests/test_stress_parallel.py) and [baseline reuse](../tests/test_stress_baseline_reuse.py) | Preserve input, candidate order, tested coverage, run metrics, ranking and resume decisions across full/reduced evidence and worker counts. |
| Lift study | [Lift study evaluation and relink](../amr_lift_study.py) with [building workflow tests](../tests/test_building_tutorial.py) | Preserve frozen demand sequence, per-layout and per-scenario metrics, ranking and recommendation. Check cancellation, resume and relink. |
| Human contingency | [Study evaluation](../amr_contingency_study.py) with [timing](../tests/test_contingency_timing.py), [generated demand](../tests/test_human_generation_parity.py) and [contingency workflow](../tests/test_human_contingency.py) | Preserve release allowances, carrying and staffing feasibility, candidate roster ranking, work and coverage outcomes, and study resume. The generated-return permissions defect is a baseline error to resolve before claiming full parity. |
| Playback, Investigation, evidence and exports | [Run verification](../amr_project_runs.py), [compact execution](../tests/test_compact_execution.py), [Playback](../tests/test_project_playback.py) and [Investigation](../tests/test_results_investigation.py) | Open verified evidence through the existing workbench and compare operational and rendered/exported data. Preserve ordered rows, precision, evidence identities and consumer schemas. Measure optional CSV and PDF generation separately. |
| Optional GPU timed-route candidates | Replay actual corridor candidate batches over a stable reservation view, then run hybrid managed workloads | Match candidate timing and existing CPU selection rules, including later candidates able to beat a provisional result. Include startup, packing, transfers, waits and CPU rechecks. CPU-only results determine release acceptance. |

For the managed benchmark, start elapsed timing when the prepared run is launched and stop when saved evidence is verified and ready for Playback and Investigation. Record validation and initialisation, event execution, evidence finalisation, and optional exports separately. Report process CPU, peak memory, route candidates, corridor edges and reservation entries scanned. Normalise run IDs and wall-clock metadata in parity comparisons while keeping simulation timestamps at full precision.
