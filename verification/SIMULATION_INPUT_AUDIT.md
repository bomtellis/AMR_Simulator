# LTN input audit

The audit is tied to rollback revision `9a1ae8f`. It reconciles the 480 paths flagged by the earlier LTN fixture scan across 63 fixture labels and includes the existing field contracts and additional source-reviewed contracts. The fixture list describes the historical scan. Some labels identify saved projects or benchmark fixtures outside this checkout.

Run the normal verification pack to generate the [input register](simulation_audit.py). On Windows use the project's Python environment with `python -m verification.run --isolated --output <review-directory>`. The pack writes `simulation-input-audit.json` with each path, observed fixture labels, canonical contract, runtime effect, defaults, precedence, applicable modes, source line links and linked test outcomes where available. The report gates on unclassified historical paths and broken references. The existing [configuration review](CONFIG_AUDIT_REVIEW.md) records the scope of the older field contracts. A linked passing test shows that the associated test passed. Support claims remain at the level established by the field contract and its limitations.

The fixed fixture scope preserves the original field spellings. A trailing `[]` denotes a list element. Named department maps and weekdays resolve to reviewed map contracts. The historical scanner used a wildcard for the `shift_patterns` key followed by a literal shift name. The register maps those observations to `task_generation.staff_config.shift_patterns.*`. This affects audit labels only. Group and department overrides inherit field contracts where their scopes lack an explicit one. The merger restores the category-wide drop-off capacity policy after applying an override. Legacy return-pool controls are exposed by the editor, but generated tasks do not carry the enable flag to the runtime return branch. No runtime effect is established for the multiplier or maximum.

## Verification limits

The audit unit is a fixture path or a reviewed source contract. Plugins, inputs outside the corpus, combinations of controls, and blank or disabled options require their own evidence. The earlier broad discovery report still lists raw keys found by its separate scanner. A source reference establishes a code path for review, and a workflow test establishes only the behaviour exercised by that case.

The rollback suite exposes a human-contingency defect in `test_generated_return_identity_and_passive_wait`. `HumanRouter.route` builds a preview key by sorting each permissions value. The route rules for the generated return include a boolean `profile_applied`; attempting to iterate it raises `TypeError`. That case must be resolved or explicitly excluded from any later claim of full human-workflow parity.
