# Tutorial control audit

Audited all 62 actions in the 12-part building tutorial against the live Qt workspaces and editors. The circulation chapter contributes 21 spatial actions. Guidance never writes project inputs, opens a field's tab, or accepts a dialog on the user's behalf.

Tests exercise actual widgets, tab navigation without focus theft, scrolling, picker selections, finite-coordinate validation, target validation, saved department/group generation, simulator task fields, atomic rejection and source immutability across all 62 action targets. Tutorial reference runs continue to complete 36 tasks with 12 wash cycles and both lifts.

The bubble now uses grouped, scrollable checklists for equipment, demand and proposal actions. Within dialogs, one blue value prompt sits beside the currently highlighted field and advances as draft values match. It participates in the dialog layout, preserving input and Save/Cancel access, and is removed on Pause, editor closure or target changes. Main-workspace values remain in the bubble. Exact prompts include scheduled times, run dates, route-picker permissions and lift-stop cells.

The robot editor intentionally saves Unloaded weight = Unspecified as `weight_kg: null`. Preflight now accepts this optional robot report metadata, resolving the Part 5 / Action 4 completion blocker. Payload mass remains mandatory, and negative, nonfinite, boolean and nonnumeric entered robot weights remain errors. An actual saved AMR dialog result passes the equipment chapter and its final action gate. Department diamonds are 0.8 m across rather than 1.8 m; exported DXF markers use the same scale and existing point picking remains available.

Graphical permission and demand-preview regressions exercise real canvas clicks, floor navigation, edge direction, cancellation, saved drafts and the Check-pane launcher. Drawing tools remain disabled during permission selection and restore afterwards. Deferred theme polishing ignores deleted dialog objects.


Route navigation review now uses Layout → Routes / Route view, with separate permitted and blocked edge colours, direction arrows, labels and profile details. Dotted strokes show excluded directions, including partial one-way permissions and auto-connections. Display preferences remain outside project inputs. The row can be collapsed to retain drawing space.

Run checks → Task routes evaluates manual task definitions, explicit generated task snapshots, enabled resolved demand-rule location pairs and configured returns. The audit uses directed node/edge/lift permissions, manual task-local extensions, effective group overrides, tracked-item source locations and AMR drop-off zones. Rules are checked without releasing tasks; runtime-dependent demand remains conditional. Unknown effective profiles are errors; blocked routes remain acknowledgeable constraint warnings. Route results and warnings are invalidated by edits to geometry, profiles, tasks or generation inputs, and are exported with the check report.

Review → Route checks independently evaluates the saved run input snapshot. Current project edits cannot change those results. Logs without input evidence show unavailable coverage. Route checks hide the event timeline to give the table room; normal task and metric tabs restore it. Check and Review results distinguish graph permission reachability from timing, capacity, clearance and physical completion.

Parts 10 and 11 now expose a persistent progress label and indicator above the lift planner action buttons. Evaluation names each frozen layout/scenario, tracks elapsed time, reports completion/failure and opens Scenarios. Its completion callback has a distinct name from QDialog.finished so actual QProcess completion unlocks the planner and enables proposal generation. Proposals use a background job with site-screening and connector progress; the UI remains responsive, Stop generation retains earlier proposals/evidence, and the first completed proposal is selected with its overlay. Generation failures retain the previous study. Guidance follows active preparation controls and running progress rather than disabled Evaluate/Generate buttons; stale studies cannot satisfy these action gates. Real mouse-click, worker, cancellation/resume, failed-start and event-loop responsiveness tests cover the flow.
