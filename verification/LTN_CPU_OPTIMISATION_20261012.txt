LTN CPU OPTIMISATION — IMPLEMENTED AND VERIFIED, 12 October 2026

The full seven-day LTN CPU simulation now takes 160.105 seconds against
357.453 seconds for the preserved original source: 55.21% less time
(2.23x the execution rate). Complete normalised task-record, event-stream
and operational final-state hashes are identical. The production changes are
in simulator.py, amr_route_reservations.py and amr_sim_task_generation.py.

IMPLEMENTED CHANGES

1. Idle returns: _create_idle_return_task checks whether the robot is already
stowed before doing any charging-destination routing. Other stowing, return,
charger-admission and reservation decisions retain their existing rules.

2. Lift booking tails: LiftReservations keeps complete list-compatible history
and an exact maximum-finish booking. It updates the index for insertion,
append, replacement, deletion, sorting, reversal and rollback. Equal finish
values still select the first entry, just like max. Plain lists supplied by
callers use the original linear maximum. The reliability-ordered slot query
and post-commit state update use this index; the no-wear/no-failure gap search
retains its existing floor-continuity and reservation logic.

3. Calendar caching: department operating periods are cached by their operative
schedule values, requested datetime, timezone identity and fold. The cache is
bounded at 8,192 entries, distinguishes raw argument types, and returns fresh
lists around immutable periods. Edited schedules get new keys. An explicit
allow-list with no valid day remains closed; overnight windows, equal clock
24-hour rules, legacy hours and active-day checks retain existing semantics.
Excluded timeframe members now also cache their existing (0, total) fallback;
the requested payload count and allocation among active members do not change.

4. Lift alternatives: in Simple mode, outgoing corridor travel and wait-node
selection are skipped only when the lift's own finish time already cannot
beat the best complete finish. Outgoing travel is nonnegative, and the existing
strict comparison/iteration order preserves ties. Detailed mode still performs
all outgoing geometric evaluations and certification, including losing lifts.

5. Corridor overhead: robot speed is resolved once per leg; empty people-history
queries and inactive scenario dispatch are skipped; physical-edge keys use a
direct ordering comparison; and reporting-only delay calculations are omitted
when segments are not requested. Active people/scenario effects, corridor
capacity, congestion, FIFO reservations, node waits, energy and event times
continue through their existing calculations. No coarse time steps, rounded
estimates or approximate route shortlist were introduced.

The original project's demand, inventory, robot fleet, lift wear/repair,
charging, return and 20-minute deferral settings were preserved. Mode remains
CPU Simple for LTN; no GPU, native acceleration or new parallel execution was
introduced. Project inputs were not edited.

REGRESSION AND DIFFERENTIAL CHECKS

All 47 saved verification/scenarios projects ran successfully under both the
original source and the final code. Each case matches on complete normalised
operational events, task records/outcomes, and hashed resource/robot/payload
final state. The cases include Simple/Detailed motion, recovery, routing
restrictions, lift reservation/repair, charging, stock and returns.

The final broad check ran 837 tests across 74 modules:
834 passed, 3 failed, no errors. All three failures reproduce on the
preserved original source, with the same assertions. They were not changed to
make the optimisation suite pass:
- GeometricStopTests.test_rejected_joint_admission_keeps_blockage_evidence
- GeometricStopTests.test_unfitting_retreat_stops_with_bound_reason_not_task_failure
  Both expect blocked run evidence but currently observe finished.
- RequiredChargeDispatchTests.test_selecting_a_charge_request_does_not_spend_or_reserve
  It expects an empty event queue but an existing deferral timeout remains.

The 13 new optimisation edge-case tests all pass. They cover tied/nonmonotonic
booking ends, arbitrary list mutations, copy and rollback, raw schedule types,
mutable schedules, timezone/local-day boundaries, negative allocation caching,
Simple-vs-Detailed lift pruning and active-vs-empty people checks.
An earlier focused check passed 204 tests; final calendar/contract checks passed
67 tests. Those totals overlap the broad run and are not added to it.
